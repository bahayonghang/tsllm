## 1. 固定基线与执行环境

1. 记录 Git HEAD、工作区范围、依赖锁与已安装工具版本，确认没有并发改动影响基线。
2. 导出固定提交到独立临时源码目录；只包含跟踪文件，不复制私有或忽略目录。
3. 确定依赖复用和隔离构建方式，确认输出不会写回主工作区或共享依赖。缺失依赖先报告，不自动下载。
4. 重建 B0，记录正式构建产物、哈希和依赖图；已有 web/dist 只作为历史参考，不直接替代固定基线重建。
5. 验证当前浏览器的缓存隔离、资源记录和时间观测能力；记录不支持项。

## 2. 隔离方案

1. 使用 trellis-implement 代理完成临时 B1、B2 方案和必要的测量工具，限定所有权为当前任务材料及明确临时目录。
2. 优先使用原生上下文注入；缺失时代理读取 implement.jsonl。代理不得更改主工作区产品文件，不得撤销他人改动。
3. 对照固定基线保存每个方案的最小补丁；只调整既有加载边界。
4. 对三个方案分别执行前端三项正式门槛，保留失败与修正后的记录，不删除原测试或提高警告阈值。

正式门槛在对应隔离副本内运行：

- pnpm -C <variant>/web run check
- pnpm -C <variant>/web run test
- pnpm -C <variant>/web run build

## 3. 受控测量

1. 准备同一套合成终态作业、合成指标和合成数据集缓存，记录文件哈希。
2. 检查 9000 端口与进程身份；通过现有 Settings 明确绑定三个独立临时根目录及方案 web_dist。
3. 使用进程级离线设置。若使用 uv，先检查其他 uv sync，等待冲突结束，不终止其他进程。
4. 先验证真实响应头、缓存行为和页面就绪定义，再运行 design.md 中 3×6×5 的主矩阵。
5. 保留全部有效样本和失败记录，分别计算入口、导航增量及累计成本。指标缺失时明确标注，不能补造或缩减矩阵后宣称完成。

## 4. 行为复核与关闭

1. 可见浏览器完成 390/1280 px 全页面入口、加载状态、深链接、表单预览、图表、七类警告和空值检查。
2. 临时方案的模块失败/恢复检查不替代正常生产构建的页面验收。
3. 比较服务前后合成文件哈希，确认没有作业执行、权重下载或私有访问。
4. 关闭本任务服务，确认进程退出及 9000 释放，恢复视口，不停止其他进程。

## 5. 报告与独立检查

1. 生成 report.md、verification.md 和 evidence/：环境、样本、汇总、补丁、门槛日志摘要及可复现方法。
2. 使用 trellis-check 代理独立检查证据、公式、样本数、异常和范围。优先原生上下文注入，缺失时读取 check.jsonl。
3. 独立复算资源集合与变化量，审阅测量有效性和行为边界；不能用另一份静态扫描代替实际测量。
4. 如发现实验脚本或临时方案缺陷，按 auto 流程返修并重跑受影响测量；产品范围变更须停止报告。
5. 完成前执行 git diff --check、全部新增任务材料检查、task.py validate、私有目录跟踪检查，并核对主工作区产品哈希。
