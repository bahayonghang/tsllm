# 前端加载评估设计

## 1. 责任与产物

本任务的产物是评估证据和决策报告。路由依赖由 web/src/router.tsx 管理，表单和图表依赖分别由现有功能组件管理；HTTP 行为仍由既有 FastAPI 静态服务提供。不得修改共享 API 或数据契约。

主工作区只写本任务目录。实验使用固定提交导出的临时源码副本，只含已跟踪文件；不得复制 data、ref、runs、cache、.claude 或其他忽略目录。已安装依赖可以受控复用；产物、缓存和工具输出均指向临时目录，避免写回主工作区。每个方案保存补丁和环境清单。

## 2. 对照方案

| 方案 | 唯一主要变量 | 验证的问题 |
| --- | --- | --- |
| B0 | 固定基线，不改变加载策略 | 当前入口和首次功能访问付出多少成本 |
| B1 | 保留 AppLayout 与路由路径，将页面模块改为受支持的路由延迟加载 | 路由边界能否推迟当前页面不需要的代码 |
| B2 | 在 B1 上按实际使用条件延迟表单或结果图表模块 | 更细边界是否有可测增益，是否增加请求与等待 |

先读取已安装 React Router/Vite 的类型与实现支持，再确定临时补丁。禁止按包体积猜测运行时节省量。B2 只选择实际可延后的现有功能边界；未得到更细收益也是有效结论。若无法构造符合既有行为的方案，记录失败原因，该方案不得标为通过。

不得改变 chunkSizeWarningLimit、minify、target、压缩设置或依赖版本来制造收益。所有产物体积使用没有计时探针的正式构建；若需要临时探针，三方案使用相同探针，并另列其成本。

## 3. 资源与时间口径

- 原始字节：构建文件的实际长度；注明十进制 kB 与二进制 KiB 的差别。
- 压缩估算：同一工具版本和参数逐文件计算；不能对整个目录拼接后压缩。
- 实际传输：记录 Content-Encoding、缓存状态、transferSize、encodedBodySize 和 decodedBodySize；不能从 Vite 的 gzip 列推断服务已启用压缩。
- 入口集合：从 HTML 及资源记录确定页面首次就绪前必需的资源，包括共享块和 modulepreload。
- 导航增量：记录首次点击目标入口后新加载的 URL；累计集合以同一会话的 URL 并集计算，不重复计共享块。
- 页面就绪：页面主体及对应表单或图表可用。若使用计时探针，必须等待该方案相同的合成数据和组件就绪条件；不得以 load、首个文本或工具往返时间替代。
- 浏览器支持时记录 FCP、Navigation Timing 和长任务；明确长任务不能直接解释为某个库的解析或执行时间。没有可靠观测能力时列为未测，并保留相应验收缺口。
- 每个组合至少 5 次有效观测，保留全部样本，报告中位数、最小值、最大值及失败次数。交替方案顺序，记录冷/热缓存设置，避免只保留最快结果。

## 4. 主矩阵

性能主矩阵固定 1280 px、同一浏览器和本地环回服务。每个方案覆盖以下 6 个组合，每组合至少 5 次，共至少 90 个有效观测。

1. 冷缓存直接打开 /runs。
2. 同一缓存条件下重新打开 /runs。
3. /runs 首次进入 /runs/new，表单和预览可用但不提交。
4. /runs 首次进入 /compare，使用固定合成实验与入库作业。
5. /datasets 首次进入固定合成数据集详情，等待实际图表。
6. /runs 首次进入固定合成实验详情，等待对应结果图表。

每个首次导航样本从相同入口状态开始，不继承前一个样本已访问目标页的缓存。原始记录包含 source route、target route、cache mode、variant、sample、viewport、browser version、资源集合及实际测得的时间。1280 px 用于性能比较；390 px 用于行为检查，不将窄视口结果称为真实手机性能。

不强制模拟网络或 CPU 降速。若执行环境支持且需要补充，另建标注清楚的扩展矩阵，不与主矩阵混算，也不替代主矩阵。

## 5. 服务与隐私

只使用 127.0.0.1:9000。启动前确认端口空闲，不停止其他进程。通过现有 create_app(Settings(...)) 显式传入独立临时 runs、cache、configs 和当前方案 web_dist；Settings.from_env 没有 web_dist 映射，不新增该字段或修改 CLI。

夹具只含合成终态作业、合成指标与必要的合成数据集缓存。不得启动 queued/running 作业，不调用提交、训练、入库或下载接口。服务前后检查合成作业文件哈希，模型缓存使用独立空目录。使用既有进程级离线设置和回环例外，不改网络、防火墙或 CUDA_VISIBLE_DEVICES。若调用 uv，先检查并等待其他 uv sync。

cache/datasets/ETTh1.acc-backup、.claude/launch.json、原有 web/dist 及私有根目录不写入。截图仅在会话查看。仅关闭本任务启动的服务；结束时恢复视口。

## 6. 行为与验证

B0、B1、B2 均运行前端 check、test、build，保留全部现有测试。临时加载边界增加必要的加载中、模块失败、重试/恢复和深链接检查；网络模拟在 fetch 或模块加载边界，不伪造业务 hooks。

三方案在 390/1280 px 检查所有现有页面入口、URL 参数、手工混合对比、七类警告、空值、表单预览和实际 Canvas。这些检查验证前端行为；不运行真实作业，也不重开父任务验收。

不改后端实现时，无需机械重跑后端四门槛。若发现必须修改产品、后端契约或依赖才能继续，停止相应方案并报告，不扩展任务。

## 7. 报告与决策

report.md 包含基线、方法、样本摘要、三个方案的资源/时间对照、行为门槛、实现代价和未验证项。measurement 数据与补丁保存在任务 evidence/ 下，去除临时绝对路径中的不必要机器信息，不包含原始业务数据。

建议必须同时考虑入口收益、首次使用成本、累计资源和维护复杂度。微小时间差若落在样本波动内，只报告观测结果，不宣称稳定提速。没有用户批准的性能目标，不新增任意百分比作为产品通过门槛。

报告完成后由用户决定是否另行落地产品拆分；本任务不自动修改产品、提交、归档或创建后续任务。
